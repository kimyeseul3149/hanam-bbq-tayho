# 웹 운영 대시보드 — 태블로 제작 가이드

HTML 대시보드([web-ops.html](../web-ops.html))와 **같은 숫자가 나오도록** 태블로로 옮기는 절차.
데이터 재생성은 `python docs/dashboard/_build/export_tableau.py`.

> **필요 버전** — Tableau Desktop **2020.2 이상** (관계(relationship) 기능 필수)

---

## 1. 데이터 원본 4개

| 파일 | 행 | 입자 | 역할 |
|---|---|---|---|
| `sessions.csv` | 9,505 | 1행 = 1세션 | 모든 고유 사용자 지표의 원천 |
| `cta_events.csv` | 133 | 1행 = 1 CTA 클릭 | 위치 × 유형 매트릭스 |
| `meta_daily.csv` | 53 | 소재 × 일자 | 노출·링크클릭·지출 (가산 가능) |
| `meta_unique_clicks.csv` | 6 | 소재 | 고유 링크클릭 (기간 분할 불가) |

> 계정 합계 **14,570** 은 파일에 넣지 않았습니다. `sessions`에 짝이 없어 태블로에서
> `Null` 행으로 뜨고, 총합계를 켜면 소재별 합(15,124)이 잡혀 도착률이 틀립니다.
> 전체 도착률의 분모는 **매개 변수 `p_고유클릭_전체` = 14570** 으로 고정해 씁니다.

### 연결 방법 — 반드시 **관계(Relationship)**

```
sessions  ─── creative = creative  AND  date = date ───  meta_daily
          ─── session_key = session_key ────────────────  cta_events
          ─── creative = creative ──────────────────────  meta_unique_clicks
```

> ⚠️ **조인(Join)을 쓰면 안 됩니다.**
> `sessions`와 `meta_daily`를 조인하면 하루치 지출이 그날 세션 수(수백 건)만큼 복제됩니다.
> 지출이 ₫8,816,522 → 수십억으로 부풀고 유도당 비용이 완전히 망가집니다.
> 관계는 각 측정값을 자기 테이블 입자에서 집계한 뒤 결합하므로 이 문제가 없습니다.

추출(Extract, `.hyper`)로 저장해 두세요. 데이터가 작아 즉시 완료됩니다.

## 2. 계산된 필드

### 웹 지표 — `sessions` 기준

```
[방문자]      COUNTD(IF [is_arrival] = 1 THEN [user_id] END)
[세션]        COUNTD([session_key])
[클릭 사용자]  COUNTD(IF [is_anyclick] = 1 THEN [user_id] END)
[행동 사용자]  COUNTD(IF [is_action]   = 1 THEN [user_id] END)
[CTA 사용자]  COUNTD(IF [is_cta]      = 1 THEN [user_id] END)
[예약 유도]    COUNTD(IF [is_reserve]  = 1 THEN [user_id] END)

[행동률]      [행동 사용자] / [방문자]
[예약 유도율]  [예약 유도]   / [방문자]
[인당 세션]    [세션] / [방문자]
```

> **`SUM([is_reserve])`를 쓰면 안 됩니다.** 한 사람이 여러 세션에서 예약 CTA를 누르면
> 중복 집계됩니다. 예약 유도 90명이 106건으로 나옵니다. 반드시 `COUNTD`.

> **`[방문자]`에 `is_arrival = 1` 조건이 꼭 필요합니다.** 빼면 도착 이벤트 없이 세션만
> 시작된 사용자가 섞여 8,085명이 됩니다(정답 8,084).

### 광고 지표 — `meta_daily` 기준

```
[지출]        SUM([spend_vnd])
[노출]        SUM([impressions])
[링크클릭]     SUM([link_clicks])
[CTR]         [링크클릭] / [노출]
[CPC]         [지출] / [링크클릭]
[유도당 비용]  [지출] / [예약 유도]
```

### 도착률 — 주의가 필요한 지표

```
[고유클릭_소재]  SUM(IF [creative] <> '(TOTAL)' THEN [unique_link_clicks] END)
[도착률_소재]   [방문자] / [고유클릭_소재]
```

전체 수준에서는 **파라미터**를 쓰세요.

```
파라미터  p_고유클릭_전체 = 14570   (정수, 고정)
[도착률_전체]  [방문자] / [p_고유클릭_전체]
```

> **왜 합계를 쓰면 안 되나** — 고유 클릭은 사람 수라 중복 제거됩니다.
> 소재별 합은 **15,124**지만 계정 합계는 **14,570**입니다(소재를 2개 이상 클릭한 554명).
> 태블로의 총합계는 자동으로 SUM을 하므로 15,124가 나오고, 도착률이 55.5% → 53.5%로 틀립니다.
> 소재·세트 단계에서는 합산 근사이므로 라벨에 `~`를 붙이세요.

## 3. 워크시트 (HTML 카드와 1:1)

| # | 워크시트 | 마크 | 내용 |
|---|---|---|---|
| 1 | `KPI_방문자` | 텍스트 | [방문자] + [세션]·[인당 세션] |
| 2 | `KPI_도착률` | 텍스트 | [도착률_전체] |
| 3 | `KPI_행동률` | 텍스트 | [행동률] |
| 4 | `KPI_예약유도` | 텍스트 | [예약 유도] + [예약 유도율] |
| 5 | `KPI_유도당비용` | 텍스트 | [유도당 비용] |
| 6 | `행동퍼널` | 가로 막대 | 5단계를 계산 필드로 피벗 (아래 참고) |
| 7 | `드릴다운` | 계층 막대 | 계층 `ad_set › creative_label › device` |
| 8 | `히트맵` | 사각형 | 행 `weekday_no`, 열 `hour`, 색 `[세션]` |
| 9 | `CTA매트릭스` | 사각형 | `cta_events` — 행 `cta_location`, 열 `cta_type`, 색·레이블 `CNT()` |
| 10 | `좌절신호` | 가로 막대 | Dead / Rage 사용자 수 |
| 11 | `표_소재별` | 텍스트 테이블 | 소재 행 + 전체 지표 |
| 12 | `표_일별` | 텍스트 테이블 | 날짜 행 + 지출·유도당 비용 |

**퍼널(6번)** 은 단계가 열이 아니라 값이라 피벗이 필요합니다. 가장 간단한 방법은
`단계` 라는 이름의 데이터를 5행짜리 보조 CSV로 만들어 교차 조인하거나,
집합 대신 **계산 필드 5개를 측정값으로 나란히** 놓고 `측정값 이름`을 행에 두는 것입니다.

**드릴다운(7번)** 은 `ad_set` → `creative_label` → `device`로 **계층(Hierarchy)** 을 만들고
`+` 를 눌러 펼칩니다. HTML의 클릭 펼침과 동작이 같습니다.

## 4. 필터·액션 — 여기가 핵심

Meta 실적은 **소재 × 일자**까지만 존재합니다. 웹 쪽에서만 나오는 조건으로 좁히면
분자만 줄고 분모는 그대로라 **틀린 값**이 나옵니다. 그래서 **액션이 적용될 시트를 제한**해야 합니다.

대시보드 액션 편집 창의 **대상 시트(Target Sheets)** 에서 아래 표대로 체크하세요.

| 필터 / 액션 | 웹 지표 시트<br>(1·3·4·6·7·8·9·10·12) | 유도당비용·CTR·CPC<br>(5·11) | 도착률<br>(2) |
|---|:---:|:---:|:---:|
| 기간 (날짜 범위) | ✅ | ✅ | ❌ |
| 광고세트 · 소재 | ✅ | ✅ | ✅ |
| 세그먼트 (기기·도시·언어) | ✅ | ❌ | ❌ |
| 행동 단계 (퍼널 클릭) | ✅ | ❌ | ❌ |
| 요일 × 시간 (히트맵 클릭) | ✅ | ❌ | ❌ |
| CTA 위치 × 유형 | ✅ | ❌ | ❌ |

**이유**

- **도착률에 기간 ❌** — 고유 클릭은 Meta가 조회 기간마다 따로 중복 제거해서 쪼갤 수 없습니다.
  전체 기간 값 하나뿐입니다.
- **세그먼트·시간·단계·CTA에 ❌** — Meta 지출을 "토요일 20시"나 "mobile 사용자"로
  나눌 방법이 없습니다.

체크를 빼는 대신 **해당 시트에 "필터 적용 안 됨"을 표시**하세요. HTML판은 이 경우 `—`를
띄웁니다. 태블로에서는 액션에서 제외된 시트가 그냥 전체 값을 계속 보여주므로,
**사용자가 "필터를 걸었는데 안 바뀐다"고 오해할 수 있습니다.** 시트 제목이나 캡션에
`※ 전체 기간 기준 — 기간 필터 미적용` 같은 문구를 반드시 넣으세요.

## 6. 자주 걸리는 함정 5가지

1. **조인 대신 관계** — 조인하면 지출이 세션 수만큼 복제됩니다.
2. **COUNTD 필수** — `SUM(is_reserve)`는 예약 유도를 90 대신 106으로 셉니다.
3. **고유 클릭은 더하지 말 것** — 소재별 합 15,124 ≠ 계정 합계 14,570.
4. **총합계가 행의 합과 다른 건 정상** — 소재별 방문자 합 8,217 vs 전체 8,084.
   COUNTD가 중복을 제거하기 때문입니다. 보는 사람이 "계산이 틀렸다"고 하지 않도록
   대시보드에 각주를 넣으세요.
5. **7/20은 부분일** — 광고가 하노이 13시경 시작돼 약 11시간만 집행됐습니다.
   전일 대비 비교의 기준선에서는 빼야 합니다.

## 7. 측정 한계 (대시보드에 그대로 표기)

- POS 미연동 — **실제 예약 완결은 측정 불가**. '예약 유도'가 상한선.
- 스크롤 뎁스 미계측 — 이탈 지점 확인 불가.
- `session_end`가 전체 세션의 14.9%에만 있어 **체류시간 측정 포기**.
- Dead / Rage Click은 Amplitude **휴리스틱 판정** — 89건 중 34건이 로고 오탐. 경향 참고용.
- 방문자는 로그인이 없어 사람이 아니라 **기기(device_id)** 단위.
- 소재 귀속은 **세션 단위**(첫 도착 이벤트 기준). 이벤트 단위로 집계한 원본 시트보다
  소재별 방문자가 최대 2명 적습니다.
