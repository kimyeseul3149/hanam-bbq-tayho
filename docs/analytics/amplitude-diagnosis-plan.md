# 페이지 개선 전 진단 계획 — 무엇을 보고, 무엇을 바꾸는가

기준 2026-07-24 · 워크스페이스 `dawn-cake-773363` · https://hanam-bbq-tayho.vercel.app

랜딩페이지를 수정하기 전에 Amplitude에서 확인해야 할 분석 7가지를 정리했다.
각 항목은 **"이 숫자가 이렇게 나오면 페이지의 무엇을 바꾼다"**가 미리 짝지어져 있다.
숫자를 본 뒤에 해석을 지어내지 않기 위해서다.

이벤트가 실제로 무슨 뜻인지는 [amplitude-events-guide.md](amplitude-events-guide.md),
속성 값의 전체 목록은 [amplitude-taxonomy.md](amplitude-taxonomy.md) 참조.

---

## 전제 — 지금 보이는 전환율은 틀린 숫자다

`Start Session → CTA Clicked` 퍼널에서 **1.17%**가 나오지만 이 숫자는 그대로 쓸 수 없다.
`CTA Clicked`에 예약이 아닌 행동이 섞여 있기 때문이다.

| cta_type | 예약인가 |
|---|---|
| `message_book` · `call_phone` | **예약 전환** |
| `directions_reserve` | 방문 의향 (중간 지표) |
| `view_menu` · `visit_facebook` | 전환 아님 |

1번과 2번이 이 문제를 바로잡는다. **기준선을 확정하기 전에는 다른 숫자를 해석하지 않는다.**

### 모든 차트의 공통 설정

아래 각 항목에서는 생략했다.

```
세분화 기준   Country is Vietnam
기간         최근 30일
측정         고유 사용자 (Unique users)
```

`language`와 `device_type`은 모든 이벤트에 자동으로 붙으므로(`app.js:22`),
어떤 차트에서든 그룹화 기준으로 바로 쓸 수 있다.

---

## 1. 이 트래픽은 진짜 사람인가

다른 모든 숫자의 전제다. 봇·광고 심사 트래픽이 섞이면 분모가 부풀려져 전환율이 실제보다 낮게 보인다.

```
차트     Segmentation
이벤트    Page Viewed
그룹화    Country          ← 베트남 세그먼트를 잠시 해제하고 본다
```

| 결과 | 조치 |
|---|---|
| 베트남 비중이 낮다 | **페이지가 아니라 광고 타게팅부터** 손본다 |
| 베트남이 대부분이다 | 분모가 신뢰할 만하다. 2번으로 진행 |

---

## 2. 진짜 예약 전환율은 몇 %인가

앞으로 모든 개선을 재는 기준선이다. 예약으로 이어지는 행동만 골라낸다.

```
차트     Segmentation
이벤트    CTA Clicked
그룹화    cta_type
```

| 결과 | 조치 |
|---|---|
| `message_book` + `call_phone` 합계 | **이 숫자를 기준선으로 기록한다** |
| `view_menu`가 대부분이다 | 관심은 있는데 예약까지 안 간다 → **4·5번이 핵심**이 된다 |

---

## 3. 페이지 문제인가, 광고 문제인가

**분기점이다.** 소재별 전환 편차가 크면 페이지를 아무리 고쳐도 효과가 적다.
UTM 수집은 이미 검증돼 있고 `utm_term`에 광고 세트가 들어온다.

```
차트     Funnel Analysis
1단계    Page Viewed
2단계    CTA Clicked
        필터  cta_type is message_book, call_phone
그룹화    utm_campaign → 그다음 utm_term
```

| 결과 | 조치 |
|---|---|
| 소재 간 편차가 크다 | **낮은 소재를 끄는 것이 페이지 수정보다 효과가 크다.** 여기서 멈춘다 |
| 모든 소재가 고르게 낮다 | 페이지 쪽 문제다. 4번부터 파고든다 |

---

## 4. 어떤 버튼이 실제로 눌리나

떠다니는 아이콘 버튼이 인지되지 않는다는 가설을 **새 계측 없이 지금 데이터로** 검증한다.
버튼마다 위치가 `cta_location`에 기록돼 있다.

```
차트     Segmentation
이벤트    CTA Clicked
        필터  cta_type is message_book, call_phone
그룹화    cta_location
```

| cta_location | 위치 | 모바일에서 라벨 |
|---|---|---|
| `hero` | 첫 화면 큰 버튼 | 있음 |
| `header` | 상단 메신저 | **없음 (아이콘만)** |
| `floating` | 우하단 전화 | **없음 (아이콘만)** |
| `visit_section` | 하단 방문안내 | 있음 |

| 결과 | 조치 |
|---|---|
| `hero`가 압도하고 `header`·`floating`이 거의 0 | **아이콘 버튼에 라벨을 단다** |
| `floating`도 잘 눌린다 | **버튼은 건드리지 않는다.** 원인은 다른 곳에 있다 |
| `visit_section`이 거의 0 | 하단까지 내려오는 사람 자체가 없다는 뜻 |

모바일에서 라벨이 사라지는 근거는 `styles.css:1474`(전화)와 `styles.css:1485`(메신저)다.

---

## 5. 모바일이 데스크톱보다 나쁜가

**이미 실험이 돌아가고 있다.** 데스크톱은 버튼에 글자가 있고 모바일은 아이콘만 있으니,
같은 페이지의 두 버전을 비교하는 셈이다.

```
차트     Funnel Analysis
1단계    Page Viewed
2단계    CTA Clicked
        필터  cta_type is message_book, call_phone
그룹화    device_type
```

| 결과 | 조치 |
|---|---|
| 모바일이 뚜렷하게 낮다 | **라벨 문제 확정.** 4번 결과와 합치면 근거가 단단해진다 |
| 차이가 없다 | 라벨은 원인이 아니다. 6·7번으로 넘어간다 |

---

## 6. 베트남어가 기본인 게 맞나

방문자가 영어로 바꾼다면 타겟이 현지인이 아니라 교민·외국인일 수 있다.
그러면 카피와 기본 언어 자체를 다시 봐야 한다.

```
차트 A   Segmentation
        이벤트  Language Switched
        그룹화  to_language

차트 B   Funnel Analysis
        Page Viewed → CTA Clicked (예약 유형만)
        그룹화  language
```

| 결과 | 조치 |
|---|---|
| vi→en 전환이 많다 | **영어 노출을 앞으로** 빼거나 광고 타겟을 재검토한다 |
| 영어 사용자의 전환율이 훨씬 높다 | **베트남어 카피가 약하다**는 신호 |

---

## 7. 어떤 메뉴가 관심을 끄나

메뉴 상세를 연 사람만 잡히므로 수는 적지만, **무엇을 골랐는지는 정확하다.**
가격까지 함께 기록돼 있어 가격 저항을 볼 수 있다.

```
차트     Segmentation
이벤트    Menu Item Viewed
그룹화    item_name_ko     → 상위 메뉴
        item_category    → 어느 분류에 몰리나
        item_price_vnd   → 어느 가격대를 열어보나
```

| 결과 | 조치 |
|---|---|
| 특정 메뉴에 몰린다 | **그 메뉴를 맨 위로** 올리고 히어로·광고 소재에 쓴다 |
| 저가 메뉴만 열어본다 | **가격 저항.** 세트·프로모션 노출을 강화한다 |

## 지금은 측정할 수 없는 것

아래 세 가지는 위 분석으로 답이 나오지 않는다. **데이터가 없다는 사실 자체를 알고 해석해야 한다.**

### 어디까지 스크롤하고 이탈하는가

심어진 이벤트가 전부 클릭 기반이라, 눈으로 보기만 하고 나간 사람은 흔적을 남기지 않는다.
`Menu Item Viewed`는 "메뉴를 봤다"가 아니라 **"카드를 눌러 상세 팝업을 열었다"**만 센다.

→ `Section Viewed`(섹션이 화면에 들어오는 순간 기록)를 추가해야 답이 나온다.
[amplitude-taxonomy.md](amplitude-taxonomy.md)에 미구현으로 적혀 있는 이벤트다.

### 메신저 버튼이 실제로 열렸는가

`CTA Clicked`는 **눌렀다**까지만 기록한다.
카카오톡·잘로 인앱 브라우저에서는 눌러도 메신저가 열리지 않는데, Amplitude에는 성공으로 잡힌다.

→ **실제 전환은 지표보다 더 낮을 수 있다.**

### 정말 예약으로 이어졌는가

Amplitude는 버튼 클릭까지만 안다.
매장에 실제로 들어온 메신저 문의 수·전화 수와 대조해야 진짜 성과를 알 수 있다.
이 대조 없이는 어떤 수치도 반쪽이다.

## 실행 순서

한 번에 다 하지 않는다. 앞 단계 결과가 뒤 단계를 건너뛰게 만들 수 있다.

| 순서 | 항목 | 이유 |
|---|---|---|
| **먼저** | 1 → 2 | 트래픽이 진짜인지 확인하고 기준선을 확정한다. 이게 없으면 나머지 해석이 전부 흔들린다 |
| **분기** | 3 | 광고 소재 편차가 크면 **여기서 멈추고 소재부터 정리한다.** 페이지 수정은 그다음 |
| **페이지** | 4 + 5 | 묶어서 본다. 두 결과가 같은 방향이면 버튼 라벨 수정의 근거가 된다 |
| **콘텐츠** | 6 → 7 | 언어·메뉴 구성은 버튼보다 뒤에 본다. 효과가 나타나는 데 시간이 더 걸린다 |
| **그다음** | — | 여기까지 해도 이탈 지점이 안 보이면 `Section Viewed`를 추가해 며칠 쌓은 뒤 다시 본다 |
