## 2026-07-27 · 광고 7일차 — 페이지를 더 수정하지 않기로 결정

### 결정

**광고 운영 중에는 웹페이지를 추가로 수정하지 않는다.** 성능 개선·명백한 버그 수정만 예외로 하고,
전환 최적화 목적의 실험성 수정은 하지 않는다. 분석은 광고 종료 후 전체 데이터로 1회 수행한다.

### 배경 — 7일간 진단으로 확인한 것

| 항목 | 결과 |
|---|---|
| 진짜 예약 전환율 (`message_book` + `call_phone`) | **약 1.4%** (퍼널 기준 44건 / 약 3,800명, 베트남) |
| 광고세트별 편차 | business 1.39% / family 0.78% — 둘 다 낮고, 한쪽만 튀지 않음 (유의성 미확정) |
| 버튼 인지 문제 (떠다니는 아이콘 가설) | ❌ **아님** — `floating`(18)이 `hero`(21)와 대등하게 눌림 |
| 전환 발생 위치 | 첫 화면(`hero`) + 고정 버튼(`floating`)에 87% 집중, 하단(`visit_section`)은 사실상 0 |
| device | 전환자 전원 `mobile` (데스크톱 코호트 없음) |

명백한 결함이 없고, 남은 후보는 "첫 화면 설득력"(소프트 가설)과 "트래픽 의향"(가이드라인상 '트래픽' 목표로 고정)뿐이다.

### 왜 수정하지 않는가

1. **측정 기준 오염** — 7일간 전환이 약 44건뿐이다. 여기서 페이지를 바꾸면 before/after가 각 ~22건으로 쪼개져,
   전환 변화가 수정 효과인지 노이즈인지 **구분할 수 없다.** 고쳐도 증명 불가 + 유일한 깨끗한 데이터셋을 스스로 훼손.
2. **남은 사용 기간 1주** — 2주 프로젝트 페이지의 절반이 지났다. 최적화 효과가 나타날 시간이 없다.
3. **명백한 결함 없음** — 위 진단으로 버튼·메신저·광고세트·소재 결함을 모두 배제했다.

### 예외 — 이미 반영한 것 (되돌리지 않음)

- **폰트 셀프호스팅 (로딩 약 1.2초 단축, FCP 3.8→2.6초)** — 성능 개선이라 before/after 전환 증명이 불필요하고
  (빠른 게 무조건 나음), 로딩 전 이탈(도착률 손실)에 대응하는 구조적 개선이다. 반영·검증 완료.
- 판단 기준: **성능·명백한 버그**만 고치고, **전환 최적화 실험은 하지 않는다.**

### 대신 하는 것

- 광고 **종료 후** 2주 full 데이터로 분석 1회. 목적은 "이 페이지 고치기"가 아니라 **"다음 프로젝트 페이지를 위한 학습"**
  (이 페이지는 곧 은퇴).
  1. 최종 예약 전환율 (완주 데이터)
  2. business vs family — 표본 커진 뒤 유의성 재판정
  3. 세션 리플레이로 "왜 안 눌렀나" 관찰 → 차기 페이지 설계에 반영
- 운영 중에는 **매일 퍼널로 캠페인 건강만 모니터링**한다 (설정 고정, 이상 감지 용도). → [진단 계획](amplitude-diagnosis-plan.md) 참조.
